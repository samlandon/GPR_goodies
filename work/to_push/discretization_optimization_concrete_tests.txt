%%%
I think we can get good results using 0.01m discretization, which any smaller goes crazy on time, but I'll test it and save tests and their result files, if possible, here (since they 
may take many minutes to run at small discretization. I will try out 0.01, 0.005, and 0.002 (chosen because the cells will need to match the objects placed in the box, and these seem
like they will match most objects).
%%%

^REMEMBER any time you change radius, reposition so still 1m away or chosen distance


@@ EM Wave stuff @@

/#waveform: ricker 50 6e8 my_pulse
^What happens if A=1 increased to 5? Nothing. Even if bumped up to 50, no difference!

//Ascan parameters
#hertzian_dipole: z 2.300 1.100 0.500 my_pulse

#rx: 2.300 0.900 0.500 



// old Bscan parameters
/#hertzian_dipole: z 2.300 0.800 0.500 my_pulse     
^5 iter position
/#hertzian_dipole: z 2.300 0.900 0.500 my_pulse     
^10/20 iter position

/#rx: 2.300 0.600 0.500                               
^5 iter position
/#rx: 2.300 0.700 0.500                               
^10/20 iter position

% % %
When running dif iteration numbers, run rx and tx at different positions to recenter
i.e. 10 iter start 0.5 to 1.5 (so 0.4rx and 0.6tx), 20 iter had to drop stepsize to 0.05 and ran from same location
and for og, start 0.8 to 1.2 (so rx: 0.7 and tx: 0.9) with 0.1 stepsize
% % %

%% remnant from Bscanning. See og in AtoBscan/Working_con.../og...
%% #src_steps: 0 0.1 0
^5/10 iter stepsize
/#src_steps: 0 0.05 0
^20 iter stepsize
%% #rx_steps: 0 0.1 0
^5/10 iter stepsize
/#rx_steps: 0 0.05 0
^20 iter stepsize
% % % let's try doing 10 steps at 0.1m stepsize
Max_iters = 50, so optimal is lowest spacing of 2, then scale up for even spacing between start and end, which should be ...? 16 again? and this is not even max, because you
could go all the way and start at .4 and .6 and end at 1.4 and 1.6
